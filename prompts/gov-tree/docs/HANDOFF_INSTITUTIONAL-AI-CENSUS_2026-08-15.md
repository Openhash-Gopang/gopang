## 3. 확립된 작업 순서 (그대로 반복할 것)

1. **웹검색으로 division(과·팀 단위) 조직도 조사** — 우선순위: 기관 공식
   홈페이지 조직도 > 국가법령정보센터 직제 > 나무위키/위키백과(교차검증용)
2. **기존 템플릿 재사용 우선 검토** — 새 템플릿을 만들기 전에 5개 기존
   템플릿(§2 목록) 중 하나로 충분한지 먼저 판단한다. "위원회+사무처"
   구조는 거의 다 `SP-COMMISSION-ADMINDIV-TEMPLATE`로 커버된다.
3. **마스터데이터 JSON에 추가** — 기존 파일을
   `git show origin/main:<경로>`로 받아와서 append하는 방식(새로 만들지
   않음). `실사현황` 필드에 조사일·방법·완료/보류/미착수 사유를 정직하게
   기록한다.
4. **로드맵 문서 갱신** — `reports/hondi-institutional-ai-roadmap.html`을
   `origin/main`에서 받아와 §6 체크리스트(☐→☑)와 §6-10 실사 기록 로그에
   한 줄 추가.
5. **패키징**: 파일이 3개 이상이면 zip 하나로 묶는다(사용자 선호).
6. **PowerShell 적용 지시**: 브랜치명에 **반드시 날짜(YYYYMMDD)를 포함**
   시킨다(`census/NN-설명-20260815`) — 브랜치 이름 재사용으로 인한
   오염 사고가 여러 번 있었다(§5 참고).
7. **PR 생성 후, 병합 전에 diff를 직접 검증**한다 —
   `git diff origin/main origin/<branch> --stat`로 파일 목록·라인 수가
   의도한 대로인지 확인 후에만 병합을 안내한다.
8. **병합 후 반드시 `origin/main`에서 재확인**한다 — "병합했다"는 사용자
   보고를 그대로 믿지 말고 직접 fetch해서 파일 존재·체크리스트 상태를
   검증한다.

## 4. 정직하게 처리한 원칙들 (계속 지킬 것)

- **비공개 기관은 체크하되 "비공개 확인"으로 기록**한다(국가정보원·
  대통령경호처 사례) — 실사 실패가 아니라 실사 결과다.
- **조직 구조가 없는 기관도 그 사실 자체를 기록**한다(사법정책연구원
  사례 — flat 연구직군 구조).
- **시간 관계상 못 한 항목은 "미착수/이월"로 솔직히 남기고 억지로
  채우지 않는다**(국가안보실·BMTC 첫 배치, NAFI·NANET 등).
- **출처 간 수치가 다르면 최신·공식 출처를 채택하고 불일치 자체를
  기록**한다(법원행정처 4실2국 vs 4실3국, NEC 1실5국 vs 2실6국 등).
- **곧 바뀔 예정인 구조는 그 사실을 명시**한다(대법관 14명→26명 증원에
  따른 대법원 재판부 재편 논의, 2028~2030년 시행 예정).

## 5. 이번 세션에서 겪은 사고와 교훈 (재발 방지용)

- **브랜치 이름 재사용 충돌**이 여러 번 발생 — `git checkout -b`가
  "이미 존재함"으로 실패하면 현재 브랜치(대부분 `main`)에 머문 채
  후속 명령이 실행돼, 커밋이 엉뚱한 곳에 붙거나 `git push origin
  <이름>`이 오염된 로컬 브랜치를 원격에 푸시하는 사고로 이어졌다.
  → **브랜치명에 날짜를 넣는 것으로 예방 중**(§3-6).
- **로드맵 문서를 PR로 처음 병합할 때, desktop.html 탭 삽입이 별도
  PR에 있었는데 "중복이니 닫으라"고 잘못 판단해 실제로 탭 링크가
  유실된 적**이 있었다 — 이후 병합 전 diff를 직접 대조하는 습관(§3-7)
  으로 방지 중.
- **PowerShell `Set-Content`가 UTF-8 BOM을 추가**하는 부작용이
  desktop.html 편집 시 한 번 있었다 — 치명적이진 않으나 diff에
  `-<!DOCTYPE html>`/`+﻿<!DOCTYPE html>`로 나타나면 이 때문임을 알아둘 것.
- **JSON 마스터데이터를 파이썬 `json.dump(indent=2)`로 재저장하면
  포맷이 전체적으로 바뀌어 diff가 실제보다 훨씬 커 보인다** — 데이터
  손실은 아니지만, 리뷰 시 "왜 300줄이 바뀌었지?"라고 놀라지 않도록
  미리 안다.
