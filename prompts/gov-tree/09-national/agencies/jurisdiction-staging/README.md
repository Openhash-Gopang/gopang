# 국가기관 지사 관할구역 — 리서치 스테이징 (2026-08-08)

이 디렉터리는 `national-agency-master-data.json`(도메인+도코드+지사명 형식)에
바로 넣을 수 있는 **최종 스키마가 아니다**. 각 도메인 관할구역을 도메인당
공식 출처 1건씩 대조해서 모은 **원자재(raw) 데이터**다. 다음 세션에서
`_fetchNatText()`가 실제로 조회하는 스키마로 변환하는 작업이 남아있다.

## 각 파일의 `신뢰도` 필드를 반드시 확인할 것

이 파일들은 신뢰도가 균일하지 않다. 파일 최상위에 `신뢰도` 필드가 있으면
그 값을 그대로 믿고, 없으면 원문(법령 별표)을 직접 확인해서 만든 것이므로
높은 신뢰도로 취급해도 된다.

## 아직 손도 못 댄 6개 도메인

`nhis`(건강보험), `nps`(국민연금), `labor`(근로복지공단), `laborimprove`(고용노동청),
`immigration`(출입국), `post`(우정청), `probation`(준법지원센터), `bok`(한국은행)

이 중 nhis·nps·labor 3개는 **"4대사회보험 정보연계센터"**(공식 통합 사이트,
행정동 단위 관할구역 제공)가 출처로 이미 확인됐다 — 실제 데이터 추출만
남았다. 나머지는 출처 확인부터 시작해야 한다.

## 검증 방법론 (재사용할 것)

1. `law.go.kr`, `data.go.kr` 등 정부 사이트는 robots.txt로 자동 접근이 전부
   막혀 있다 — `web_fetch`로 직접 못 읽는다.
2. `namu.wiki`는 robots 차단이 없고, 각 기관 문서에 해당 시행규칙 별표
   원문을 그대로 인용해둔 경우가 많다 — 이 경로로 `tax`, `customs`,
   `coastguard`를 성공적으로 구축했다.
3. 도메인마다 먼저 `"[도메인명] 나무위키 관할구역"`으로 검색 → 나무위키
   문서가 있으면 `web_fetch`로 전문을 가져와 관할구역 표를 파싱.
4. **다중 지사 도메인(도 하나에 지사 여럿)에서 "대표 지사 하나"로
   퉁치지 말 것** — tax/nhis/nps처럼 실제로 여러 지사가 있는데 하나만
   골라 채우면, 그 지역 대부분 사용자에게 틀린 답이 나간다(2026-08-08
   완도해양경찰서 오매칭 사례로 실측 확인됨).
5. 확인 안 된 값은 절대 확정처럼 적지 말 것 — 반드시 파일 최상위
   `신뢰도` 필드에 명시. 확인 안 된 데이터를 정상 데이터처럼 섞어서
   넘기면, 이후 세션이 검증 없이 그대로 믿고 쓸 위험이 있다(이번
   세션에서 weather·mma를 만들다가 실제로 이 실수를 했고, 발견 즉시
   `신뢰도` 필드를 추가해서 고쳤다).
