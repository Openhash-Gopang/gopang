# HANDOFF 2026-08-07 · 의사·변호사 세부분야 대폭 확장 계획

> 이 문서는 기존 §5(physician→내과/외과/신경과, lawyer→형사법/민사법/
> 기업법무 각 3개)를 **현실의 공식 분류 기준으로 대폭 확장**하기 위한
> 계획서다. CONSULT_SPECIALIST(동적 자문 호출) 메커니즘과 §6 코드
> (`parentKey` 재귀 조립)는 이미 구현·검증 완료 상태 — 이 문서는
> **SP 콘텐츠 확장 작업만** 다룬다.

## 0. 근거 자료 (2026-08-07 확인)

- **의사**: 「전문의의 수련 및 자격 인정 등에 관한 규정」(대통령령) 제3조,
  law.go.kr 원문 확인. 26개 전문과목 — 1996년(39회 시험)부터 현재 체계
  정착.
- **변호사**: 대한변호사협회 「변호사 전문분야 등록에 관한 규정」 별표1

  변호사 본인이 최근 3년 내 해당 분야 사건 20~30건 수임 실적을 등록

## 2. 변호사(lawyer) — 62개 전문분야

**이미 있음(3개, 근사 매핑)**: 민사법, 형사법, lawyer-corporate(≈회사법+
인수합병 통합).

**타 페르소나와 중복 — 신설 제외(12개)**:

| 전문분야 | 중복 대상 페르소나 |
|---|---|
| 노동법, 산재 | labor-attorney(공인노무사) |
| 조세법, 법인세, 상속증여세, 국제조세 | tax-accountant(세무사) |
| 관세 | customs-broker(관세사) |
| 지적재산권법, 특허, 상표, 저작권, 영업비밀 | patent-attorney(변리사) |

이 12개는 변호사도 법적으로 다룰 수 있는 영역이지만, **이 플랫폼은
이미 그 실무를 전담하는 별도 자격직 페르소나를 두고 있다** — 중복
신설하면 라우팅 혼란(사용자가 "노동법 상담"이라고 했을 때 labor-attorney와
lawyer-labor 중 어디로 갈지)과 콘텐츠 이원화(같은 주제를 두 SP가 따로
관리)가 생긴다. 대신 lawyer-corporate 등 관련 세부분야의 IDENTITY
경계 문단에서 "이 영역은 OO 페르소나로 연계"를 이미 하듯, 나머지도
동일 패턴을 따른다.

**남은 47개**를 실제 분쟁 빈도·이 플랫폼 사용자층(개인 이용자 중심)
기준으로 4개 배치로 편성한다:

|---|---|
| 가사법 + 이혼 | **통합** → `lawyer-family`(v1.0) 하나로 신설(§5 H5 판단) |
| 상속 | 신설(`lawyer-inheritance`, v1.0), 세무사(상속증여세)·가사법과 경계 명시 |
| 부동산 + 임대차관련법 | **통합** → `lawyer-realestate`(v1.0) 하나로 신설(§5 H5 판단) |
| 교통사고 | 신설(`lawyer-traffic`, v1.0), 손해사정사·손해배상 세부분야와 경계 명시 |

| 등기·경매 | 신설(`lawyer-auction`, v1.0), 법무사·부동산 세부분야와 경계(경매 절차 자체 전담) |

## 3. 공통 설계 원칙 (기존 §5 그대로 적용)

각 신규 자식 SP는 §5 규칙대로 다음만 담는다 — 그 이상은 금지:
1. 세부분야 경계 문단(인접 세부분야·타 페르소나와의 경계 — 위 표의
   "비고"가 그 재료)
2. Tier 테이블(그 분야 특유 환각 위험)
3. L2·L3 심화 모듈
4. STEP R 3훅(변호사) 또는 STEP R-1v 자문호출 훅 확장

부모 SP(physician/lawyer)의 STEP R-1v(자문호출 판단기준) 소절에도
새 자식이 생길 때마다 "언제 이 자식을 부르는가" 한두 문장씩 추가해야
한다 — 지금 3개 기준으로 쓰인 판단기준 목록이 자식 수만큼 늘어난다.

`getConsultableChildren('physician')`/`getConsultableChildren('lawyer')`가
자동으로 새 자식을 인식하므로(레지스트리 등록만 하면 CONSULT_SPECIALIST가
즉시 그 자식을 호출 대상으로 인정) 코드 변경은 필요 없다 — SP 콘텐츠
작성 + `expert-registry.js`/`sp-catalog.json` 등록만 하면 된다.

## 4. 실행 순서 제안

1. **의사 배치 1(5개)** — 고빈도 필수과, 다른 기존 페르소나와의 경계가
   가장 많이 걸리는 배치라 먼저 처리하며 경계 설정 패턴을 확립.
2. **변호사 배치 1(8개)** — 개인 생활분쟁, 이 플랫폼 사용자층에 가장
   직접 와닿는 영역.
3. 이후 배치는 앞선 배치에서 확립된 패턴을 참고해 순차 진행 — 매 배치
   완료 시 §6 회귀 테스트(`expert-base-composition.test.mjs`) 재실행,
   catalog 고아참조 스캔 필수(지난 세션에서 실제로 발생했던 사고 재발
   방지).
4. 착수 전 다음 열린 질문을 먼저 확정할 것:
   - 가정의학과를 세부분야로 분리할지, physician(부모) 자체로 흡수할지
   - 이혼/가사법/상속을 개별 유지할지 통합할지
   - 배치4(국제·신산업, 22개)는 실제로 착수할지, 스코프에서 뺄지
