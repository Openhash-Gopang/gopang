### BUG-001
- **증상:** C-08 테스트 실패 — event-bus.js에 'plugin-registry' 문자열 포함
- **원인:** 주석 예시 코드에 'plugin-registry' 포함 → 텍스트 검색 오탐
- **조치:** 주석에서 해당 문자열 제거
- **교훈:** 텍스트 검색 시 항상 `import` 구문 한정 검사

### BUG-002
- **증상:** O-01 실패 — χ²=51.97, L1 분포 편향
- **원인:** hex 3자리(0~4095)를 1000으로 mod 시 BigInt 미사용
- **조치:** `parseInt` → `Number(BigInt(hash) % 1000n)`
- **교훈:** 대용량 정수 mod 연산은 반드시 BigInt 사용

### BUG-003
- **증상:** A-14 실패 — 오류 플러그인이 등록 거부됨
- **원인:** PluginValidator가 `classify()` 실행 오류를 등록 거부 조건으로 처리
- **조치:** validator에서 classify 실행 검사 제거

### BUG-004
- **증상:** K-10 실패 — 코어 파일에 'k-law' 포함 오탐
- **원인:** event-bus.js 주석에 'k-law' 포함 (BUG-001 동일 패턴)
- **조치:** import 구문 한정 검사로 변경

### BUG-005~007
- **증상:** G-01, G-05, G-06 실패
- **원인:** 테스트 조건 오류 (클램핑, 경계값 `<` vs `<=`, 부동소수점 오차)
- **교훈:** 부동소수점 비교 시 `Math.abs(a - b) < epsilon` 사용

### BUG-008
- **증상:** H-07 실패 — MEDICAL_ALERT 미발행
- **원인:** `hasMedFlag` 조건이 Fast-Path S3 시 legalFlags=[] 이라 발행 차단
- **조치:** `hasMedFlag` 조건 제거, riskLevel === 'S3' 조건만 사용

### BUG-009
- **증상:** B-01~B-09 전체 실패 — 파일 없음
- **원인:** ROOT = `join(__dirname, '../../..')` → `/home/claude` 오계산
- **조치:** `join(__dirname, '../..')` 로 수정

### BUG-010
- **증상:** I-02, I-08 실패 — MED 플래그 미반환
- **원인 1:** fastPath S3 후 classify() 미실행 (break로 루프 종료)
- **원인 2:** MED-01 regex `무허가.*의료|무면허.*진료` → `무허가 병원` 미매칭
- **조치 1:** break → Set으로 변경, 모든 플러그인 classify 실행 보장
- **조치 2:** regex `무허가.*(의료|병원)|무면허.*(진료|수술)` 로 확장

### BUG-011 ⭐ 가장 중요 (배포 오류)
- **증상:** `SyntaxError: does not provide an export named 'AIPipeline'`
- **발생:** hondi.net 최초 배포 시 흰 화면
- **원인:** `app.js`가 존재하지 않는 export 이름으로 static import
  - `AIPipeline` → 실제: `runPipeline` (함수)
  - `PluginRegistry` → 실제: `registry` (싱글톤)
  - `PDVLayer`, `OpenHashLayer`, `NetworkLayer`, `GDCLayer`, `PrivacyLayer` → 존재하지 않음
  - `{ KLawPlugin }` → 실제: default export
- **조치:** `app.js` 실제 export 이름에 맞게 전면 재작성
- **재발 방지:** `01-system-map.md §2 Export 이름 일람` 항상 먼저 확인

  수정은 라우팅 정확도(오분류 비용이 낮은 영역)에만 적용했다. 또한
  "교통사고사실확인원"⊃"교통사고"·"실종 예방 사전등록"⊃"실종" 같은
  접미사형/의미형 충돌(키워드 뒤에 뭐가 붙어서 의미가 바뀌거나, 접두사
  없이도 문맥이 다른 경우)은 이 "앞 글자 검사" 방식으로 못 잡는다 —
  이건 여전히 EMERGENCY_RE 전용 화이트리스트가 담당하며, 이번 구조적
  수정과 충돌하지 않는다(서로 다른 시스템, 서로 다른 위험 프로필).
- **검증:** `classifyFn=null`(순수 키워드 경로) 고정 재현으로 원복된
  bare '비자'/'입영'이 더 이상 "소비자"/"수입영수증"에 오매칭 안 됨을
  확인, 동시에 "비자 발급받고 싶어요"·"입영통지서... 연기하고 싶어요"
  같은 정상 발화는 여전히 정확히 매칭됨을 확인(회귀 없음).
  `gov-router-2026-08-21-session-smoketest.test.mjs` 29/29 유지.
- **효과:** 이 수정 이후로는 코드베이스 어디에 새 키워드를 추가하든
  (city-dept·national·L2·agency/org 등 12개 지점 전부) 부분 문자열
  충돌로부터 자동으로 보호된다 — BUG-025/030/031류 버그가 매칭
  메커니즘 차원에서 재발하지 않는다. 앞으로 짧은 키워드를 추가할 때
  "이 단어가 다른 흔한 단어에 삼켜질 위험이 있는지" 개별 검토할 필요가
  구조적으로 사라졌다.
- **교훈:** "오류가 생기면 그 사례만 고치지 말고 매칭 메커니즘 자체를
  고쳐라"는 지적이 정확했다 — BUG-031 직후 곧바로 같은 클래스의 패턴을
  재검토하지 않았다면, 미래에 같은 종류의 충돌이 계속(예: 다른 2글자
  키워드가 또 다른 흔한 단어와 우연히 겹칠 때마다) 재발했을 것이다.
  구조적 수정 후 기존 화이트리스트 패치를 "원복해서 재검증"하는 것이
  그 수정이 진짜 근본적인지 증명하는 가장 확실한 방법이었다.
- **커밋:** `refactor(gov-router): 키워드 매칭 어절 경계 인식 전면 도입 — BUG-025/030/031 근본 원인 제거 (BUG-033)`

### BUG-034 (근본적 정상화 — EMD 계층 즉시확정의 구조적 비대칭 제거)
- **발생일:** 2026-08-23
- **Phase/위치:** 지방행정AC / `src/gopang/gov/gov-router.js`
  (`emdMatchedViaTextItself` 신설, `emdFallback` 신설 — 1단계 emdMatch
  확정 로직 전면 재구성)
- **배경(사용자 라이브 스모크테스트 실측, 재차 "근본 논리 구조를
  고치라" 지시):** BUG-032(EMD "규칙 F" LLM 구제망) 병합 후 "정부24
  전수취합 코퍼스" 350건을 7개 배치 전부 라이브로 재실행한 결과,
  BUG-032가 일부는 실제로 고쳤지만(자동차세·건축물대장·재산세·
  시가표준액 등이 정확히 시청 국으로 감) **여전히 대부분(체감상
  350건 중 다수)이 "토지대장등본"·"대학 성적증명서"·"채무정보 조회"
  처럼 전혀 무관한 내용까지 포함해 전부 `SP-EMD-애월읍`으로 확정됨**을
  확인. "땜빵 말고 근본 논리 구조를 고치라"는 재지시를 받고 원인을
  더 깊이 추적.
- **근본 원인:** `_matchCity()`는 "발화 자체에서 매칭됐는지, 위치
  힌트로만 매칭됐는지"를 `_matchedViaTextItself`로 반환해서, 힌트로만
  매칭되면 `cityOnlyFallback`에 담아 즉시 확정하지 않고 뒤 단계(L2/
  국가기관/전역 분류)에 먼저 기회를 준 뒤 최후의 수단으로만 쓴다.
  그런데 `_matchEmd()`는 이 구분 자체가 없다 — 텍스트 매칭이든 위치
  힌트 매칭이든 구분 없이 하나의 `emdMatch`로 합쳐지고, BUG-032의
  city-dept LLM 체크가 NONE을 반환하면 **다른 계층(L2/국가기관/전역
  분류)을 시도해볼 기회조차 없이** 곧바로 EMD로 확정하고 함수가
  종료됐다. 실제 AC는 항상 정확한 위치(읍면동까지)를 알기 때문에
  `emdMatch`가 "위치 힌트로만" 성립하는 게 실사용의 기본값인데, 이
  경로에 city-level과 동일한 "보류 후 뒤 단계에 기회 주기" 메커니즘이
  없었던 게 진짜 근본 원인이었다.
- **조치:** `_matchCity`와 대칭적인 구조를 EMD 레벨에 이식했다.
  - `emdMatchedViaTextItself = !!_matchEmd(text, emdRecords)` — 발화
    자체에 읍면동/리 이름이 직접 언급됐는지 별도로 추적.
  - `emdFallback`(= `cityOnlyFallback`과 동일한 패턴의 "보류" 그릇)
    신설. EMD 콘텐츠(PocketBase/템플릿/팀 매칭 전부 포함)는 그대로
    생성하되, 확정(반환)할지 보류(계속 진행)할지만 조건부로 나눈다:
    - `emdMatchedViaTextItself === true`(발화에 읍면동 이름 직접 언급)
      이거나 `!classifyFn`(AI 상담 불가) → 기존처럼 즉시 확정·반환
      (고속경로, 회귀 없음).
    - 그 외(위치 힌트로만 성립 + AI 있음) → `emdFallback`에 담아두고
      **반환하지 않고 통과** — 2)cityOnly, 3)L2, 4)국가기관 재시도,
      5)전역 classifyFn 분류에 먼저 기회를 준다. 전부 실패하면 6)
      최종 폴백 직전에 `emdFallback`을 `cityOnlyFallback`보다 먼저
      확인해서 사용한다(EMD가 시청 일반보다 더 구체적이므로).
  - 부수 수정: 기존 코드가 `cityText`/`cityCode.code`를 조건 분기 이전에
    무조건 바깥 `parts`/`trace`에 먼저 push하고 있던 걸 발견해 함께
    고쳤다 — 이대로 두면 EMD를 "보류"하기로 결정해도 바깥 배열이 이미
    오염된 채로 뒤 단계에 넘어가, 뒤 단계가 다른 답을 찾아도 시청
    프리픽스가 결과에 잘못 섞이는 새로운 버그를 만들 뻔했다(구현 중
    자체 발견·수정).
- **검증:** `classifyFn=null`(AI 완전히 없음) 고정 재현 — 즉시 확정
  fast-path 유지 확인(회귀 없음). 실제 AI가 있지만 항상 NONE을
  반환하는 경우 — 모든 단계를 거친 뒤 최종적으로 emdFallback을 쓰는
  것까지 확인(최종 결과는 기존과 동일, 순서만 다름 — 절대 나빠지지
  않음). 실제 AI가 jachi를 정확히 인식하는 경우(세목별납세증명) —
  BUG-032의 효과가 그대로 유지됨을 재확인.
  `gov-router-2026-08-21-session-smoketest.test.mjs` 29/29 유지.
- **효과:** EMD가 위치 힌트로만 성립하는(실사용의 기본값) 모든 발화에
  대해, city-dept뿐 아니라 L2·국가기관·전역 classifyFn까지 전부 먼저
  기회를 얻는다 — "일단 위치를 아니까 무조건 읍면동"이라는 암묵적
  가정이 구조적으로 제거됐다.
- **교훈:** BUG-032가 "city-dept LLM 체크를 추가"하는 국소 수정이었던
  반면, 이번엔 "왜 그 체크가 실패하면 무조건 EMD로 확정되는가"라는
  더 근본적인 질문으로 한 단계 더 들어갔다 — 사용자가 "이전 패치도
  땜빵이었다"고 지적한 게 정확했다. `_matchCity`에 이미 있던 패턴을
  `_matchEmd`에 왜 안 넣었는지 자문하는 게 핵심이었다: 같은 파일 안에
  이미 존재하는 "정답 패턴"과의 비대칭을 찾는 것이 근본 원인을 찾는
  가장 빠른 방법 중 하나였다.
- **커밋:** `refactor(gov-router): EMD 즉시확정의 구조적 비대칭 제거 — city 계층과 대칭화 (BUG-034)`
