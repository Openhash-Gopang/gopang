Overview
이 문서가 왜 있는가

워크북 2종이 이 문서와 짝을 이룬다. 하나는 방법론 표(어느 영역을 어떻게 테스트할지, 116항목·13시트), 다른 하나는 그 영역들을 실제 코드에서 추출한 데이터로 항목 하나하나까지 풀어낸 상세 테스트 케이스(786항목). 두 워크북 모두 자동 필터·우선순위(P0/P1/P2) 색상 구분·진행률 집계 대시보드(COUNTIF 수식)가 포함돼 있다.

이 문서를 읽어야 하는 상황
배포 전 회귀 확인, 새 기능 추가 후 영향 범위 점검, 다음 세션 인수인계 시 "어디까지 검증됐는지" 확인이 필요할 때 이 문서와 워크북을 참조한다.
Methodology
방법론 4원칙 + 단계별 진행 순서

4원칙

  • 재발명 금지 — 이미 있는 27개 CI 워크플로·6개 라이브 스모크테스트 하네스를 대체하지 않고 인벤토리화만 한다.
  • 사고 재현 우선 — docs/의 인시던트 문서와 이번 세션 GWP 수정을, 원인 규명 비용을 이미 지불한 지점이라 보고 최우선 회귀 대상으로 삼는다.
  • 계층별 분리 — AC → GWP/EXPERT/K-Intent 태그 계층 → SP → worker.js → PocketBase L1 순서로 나눠, 층을 섞어 테스트하지 않는다.
  • 동시 세션 경합 고려 — 모든 테스트 실행 전 git pull --rebase, 공유 산출물은 현재 HEAD 기준 in-place 수정만.

Gap Closure
초안에서 밝힌 두 사각지대 — 근본원인까지 추적해 해소

① worker.js 55개 메서드 미확인 → 231/231(100%) 확정

정규식 1차 추출에서 놓친 55개를 코드로 직접 추적한 결과, 원인이 세 가지였다.

  1. 17개 — 라우터 함수 내 공용 "POST 전용" 관문(request.method !== 'POST' → 405, worker.js 10902행) 범위 안이라 그 줄 자체엔 메서드가 안 적혀 있었다.
  2. 19개 — 라우터는 안 걸러도 핸들러 함수 내부(예: handleAiSetupGet/Post)에서 GET/POST를 분기하고 있었다.
  3. 11개(/auth/verify, /geocode 등) — 라우터·핸들러 어디에도 메서드 검사가 코드 자체에 없다. "못 찾은 것"이 아니라 "검사가 없다는 사실 자체가 확정된 결론"이라 "메서드 무관"으로 명시하고, 상태변경 가능 엔드포인트인데 메서드 제한이 없으면 그 자체가 검토 대상이라 판단해 우선순위를 P1로 반영했다.

② EXPERT 505개 중 51개 트리거 없음 → 사각지대 아니었음이 확인됨

expert-registry.js의 parentKey/getConsultableChildren()을 근거로 리프·중간노드를 다시 구분한 결과, 트리거 없는 항목은 전부 중간노드였다 — 리프는 0개. 혼디 EXPERT 라우팅은 2~3단계 구조다: 1단계(AC-PRO-CORE)는 professor 같은 상위 노드까지만 라우팅하고, subject-gate.js의 refineToLeaf()가 그 자식 후보(label 기준)를 경량 모델(deepseek-v4-flash)로 재분류해 리프까지 내려간다. 트리거가 없는 게 정상 설계였다 — 상세 워크북 시트3에 "노드유형" 열로 리프/중간노드를 구분하고, 중간노드는 실제 자식 label 목록 기반 2단계 재분류 테스트로 재설계했다.

그래도 남는, 진짜 한계
worker.js 요청 바디의 정확한 필수 필드 스키마는 이 표에 없다. EXPERT 505개 전량 라이브 실행 비용은 여전히 크다 — 표본추출 전략은 유효하며, 다만 이제는 "어디가 비어있는지 몰라서"가 아니라 순수 비용 문제로 범위가 좁혀졌다.
Usage
사용법
  1. 각 시트 '우선순위' 열을 P0로 필터링해 먼저 처리한다.
  2. EXPERT 505개는 리프(452개, 실제 세션이 열리는 대상)부터 표본추출하고, 중간노드(53개)는 subject-gate 공용 로직이라 대표 사례 몇 건만 확인해도 충분하다.
  3. '상태' 열에 완료라고 적으면 99_집계/99_진행현황_대시보드 시트가 자동으로 반영한다(COUNTIF 수식).
  4. 실패 항목은 이슈/PR로 전환하고, '비고' 열을 갱신해 다음 세션 인수인계 문서에 첨부한다.
