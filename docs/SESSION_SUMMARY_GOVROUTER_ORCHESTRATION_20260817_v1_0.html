Overview
이 문서가 왜 있는가

"라우팅 표를 문서화하고 검증 시나리오를 쓴다"는 조사성 작업이 어쩌다 실제 프로덕션 결함 발견·수정으로 이어졌는지, 그리고 그 과정에서 제가(Claude) 두 번 정도 잘못 판단했다가 실측으로 스스로 정정한 지점까지 포함해 남긴다. 특히 ③의 발견은 사용자가 "메타 질문"(테스트 방법론 자체의 타당성)을 던진 데서 시작됐다는 게 이 세션의 핵심 교훈이다 — 시나리오 100건을 그냥 제출했다면 이 결함은 발견되지 않았을 것이다.

③ Discovery
policy-body vs 지사 키워드 충돌 발견 — 70×34 전수 감사

사용자가 "발화에 기관명을 못박으면 테스트 의미가 있나"라고 물어서 실제로 gov-router.js를 클론해 라이브 호출해봤다. _scoreMatchTies가 text.includes(k) 순수 문자열 포함 검사라는 걸 확인했고, "법원 시설물 촬영 협조"(NCA의 정식 등록 트리거 문구!)를 그대로 넣었는데도 NCA로 안 가는 걸 발견했다. 원인은 4345행의 우선순위 가드 — _NAT_AGENCY_DOMAIN_KEYWORDS.court의 단독어 '법원'이 먼저 걸려 정책기관 매칭 자체를 건너뛰게 만들고 있었다.

_POLICY_BODY_DOMAIN_KEYWORDS(70개)와 _NAT_AGENCY_DOMAIN_KEYWORDS(34개)를 전부 파싱해 전수 대조한 결과, 2026-08-03에 이미 알려져 우회 키워드까지 추가됐던 7개(NTS·KCS·POLICE·MMA·KCG·PPS·PROSECUTION) 외에 동일 패턴의 충돌이 11개 더 있었다: CIO·CONSTCOURT·COTI·JPRI·KMA·MOEL·MOJ·MPVA·NCA·OKA·SUPREMECOURT.

실무적으로 가장 걱정스러운 패턴
"헌법재판소에 문의하고 싶어요", "법원행정처에 문의하고 싶어요", "대법원에 문의하고 싶어요"처럼 기관 이름을 그대로 말하는, 가장 자연스럽고 흔한 화법이 오히려 실패하고, 훨씬 덜 자연스러운 우회 표현만 통과하는 역설적인 상태였다.

22건(11개 기관 × 충돌표현/안전표현)을 live-policy-body-collision-audit.mjs로 직접 만들어 실행 — 가설대로 22/22 재현했다.

Lessons
교훈

메타 질문이 진짜 결함을 찾는다. "이 테스트 방법론 자체가 타당한가"라는 사용자의 질문이 없었다면 100건 시나리오는 그냥 제출됐을 것이고, 18개 기관의 라우팅 실패는 발견되지 않았을 것이다. 시나리오를 만드는 것과, 그 시나리오가 실제로 무엇을 테스트하는지 검증하는 것은 다른 작업이다.

키워드 기반 매칭에서 "포괄어 vs 구체어"는 항상 충돌 후보다. '법원'·'재판'·'보훈'처럼 짧고 일반적인 단어는 그 자체로 지사 실행 신호를 잡는 데는 유용하지만, 같은 단어가 우연히 포함된 다른 기관의 정식 명칭까지 전부 오탐 없이 걸러낸다는 보장은 없다. 이번처럼 한쪽(7개)만 수정하고 넘어가면, 똑같은 패턴이 문서화되지 않은 채 남는다.

하네스 자체도 코드다 — 버그가 난다. 이 세션에서 실제 제품 결함은 라우팅 쪽 8건이었지만, 제가 만든 검증 하네스 쪽 버그는 그보다 많은 5차례였다(placeholder API 키, 토큰 부족, 함수 실수 삭제, 멀티턴 미지원, 정상 종료 오라벨링). "테스트가 실패했다"는 신호를 받으면 제품 코드부터 의심하기 전에, 테스트 코드 자체를 먼저 의심하는 습관이 필요하다는 걸 반복해서 확인했다.
