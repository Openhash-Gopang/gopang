# 혼디 폰 필드 테스트 체크리스트 v1.0

**작성일**: 2026-07-28
**대상**: 실제 폰(hondi.net PWA)에서 AC-PRO-CORE(hondi-pro 기본화 이후) 대상 수동 테스트
**사용법**: 각 항목을 실제로 폰에 발화 → 결과를 성공(✅)·부분(🟡)·실패(❌)로 표시하고, "실제 결과"란에 무슨 일이 있었는지(어느 SP로 갔는지, 명확화 질문을 했는지, 아무 반응 없었는지 등) 짧게 적습니다. 이 문서는 `docs/HONDI_MASTER_TEST_PLAN_v1_0.md`(코드/유닛 테스트 지도)와 역할이 다릅니다 — 그건 "코드가 정합적인가"이고, 이건 "실제 대화가 사용자 눈에 정상으로 보이는가"입니다.

**우선순위 표기**: 🔴 필수(오늘 이 세션의 핵심 변경사항 검증) / 🟡 권장(알려진 위험 지점) / ⚪ 여유 있으면(전체 스모크)

## PART 3 — 이번 세션에서 코드로 확인된 알려진 위험 지점 재현 (🟡 권장)

이건 "혹시 되나 안 되나 모르겠다"가 아니라, **코드를 직접 대조해서 실제로 문제 소지가 있다고 확인한 지점들**입니다. 실패해도 놀랄 일은 아니지만, 정확히 어떻게 실패하는지(조용히 무시되는지 vs 정직하게 안내하는지)가 중요합니다.

| # | 발화 | 알려진 이슈 | 상태 | 실제 결과 |
|---|---|---|---|---|
| 3-1 | "제 프로필을 찾아줘" 또는 특정 업체 검색 요청 | **ksearch가 `status: 'pending'`**(gwp-registry.js 확인) — 아직 비활성일 가능성. KSEARCH_HANDOFF를 정확히 내도 대상이 꺼져있으면 소용없음 | ☐ | |
| 3-2 | "영화 예매해줘", "인테리어 견적 받아줘" | K-Market SP 원문(`SP-KMARKET-v2_7.txt`)에도 렌탈·예매·견적이 명시적으로 언급된 적 없음(AC 쪽 CATALOG만 이번에 보강함) — SP 자체가 이 요청을 얼마나 매끄럽게 처리하는지 확인 필요 | ☐ | |
| 3-3 | "부모님 요양원을 알아봐줘" | risk_tier=high로 분류해뒀지만, 아직 대응 SP 자체가 없는 영역(G범주) — 신중한 안내로 그치는지, 아니면 무리해서 확정적으로 답하지 않는지 | ☐ | |
| 3-4 | "동호회 모임을 만들고 싶어" | 사람과 사람을 연결하는 기능 자체가 혼디에 없음 — SP_DRAFT_REQUEST가 뜨는지, 조용히 안 된다고만 하는지 | ☐ | |
| 3-5 | "국회 법안 조회해줘", "지방의회 조례 개정안 알려줘" | risk_tier=low 대상 — §INFO 웹검색으로 실제 답을 주는지, 아니면 여전히 미루는지(0-4가 통과했다면 이것도 통과해야 정상) | ☐ | |
