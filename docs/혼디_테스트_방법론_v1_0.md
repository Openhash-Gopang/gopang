# 혼디(Hondi) 플랫폼 — 체계적 테스트 방법론 v1.0

> 작성일 2026-08-11 · gopang 허브 저장소(Openhash-Gopang/gopang) 실사 기반.
> 짝 문서: `혼디_시스템_테스트_항목표_v1_0.xlsx`(전체 116개 항목, 13개 시트).

---

## 0. 이 문서를 쓰는 이유

저장소는 방대하다 — worker.js 하나에만 REST 엔드포인트 231개, 18개 이상의
위성 저장소, `.github/workflows/` 27개, `tests/live_smoketest/` 6개
라이브 하네스, 88개+ EXPERT 페르소나. "테스트를 하자"는 지시를 곧바로
실행하면 범위가 무한정 커지므로, 아래 네 가지 원칙으로 범위를 먼저
가둔 뒤 표로 구체화했다.

## 1. 네 가지 원칙

**원칙 1 — 재발명 금지.** 저장소에는 이미 27개 CI 워크플로와 6개 라이브
스모크테스트 하네스가 있다(`.github/workflows/`, `tests/live_smoketest/`).
이 표는 그것들을 대체하지 않는다. 시트 `01_기존자동화_인벤토리`가 이미
있는 것을 전부 목록화하고, 나머지 시트는 자동화가 없는 사각지대만
신규로 설계한다.

**원칙 2 — 사고 재현 우선.** `docs/`의 인시던트 문서(`GDC_GIT_EXPOSURE_INCIDENT`,
`DEVICE_LINK_FULL_CHAIN_INCIDENT` 등)와 이번 세션에서 직접 고친 GWP
orphan-tab 버그는, 원인 규명 비용을 이미 지불해 둔 지점이다. "한 번
난 사고가 재발했는가"를 확인하는 회귀 테스트(시트
`11_회귀_인시던트_체크리스트`)가 재현 시나리오 설계 비용은 가장 낮고
재발 시 파급력은 가장 크므로, Phase 2에서 최우선으로 다룬다.

**원칙 3 — 계층별 분리.** 혼디는 다음 순서로 층이 나뉜다.

```
AC(그림자 라우터)
  → GWP / EXPERT / K-Intent 등 태그 계층
    → SP(개별 페르소나·기관·전문직)
      → worker.js(231개 REST 엔드포인트)
        → PocketBase L1
```

층을 섞어 테스트하면 실패 원인 특정이 어려워진다. 표를 시트 02(라우팅)
→ 03(관제탑 원칙/SP 구성) → 04~08(도메인별 SP·엔드포인트) → 09(위성
저장소) 순으로 층별로 나눈 이유다.

**원칙 4 — 동시 세션 경합 고려.** 이 저장소는 여러 세션이 동시에
커밋한다(`NEXT_SESSION_HANDOFF_*` 문서들이 반복적으로 지적). 모든 테스트
실행 전 `git pull --rebase`, `sp-catalog.json` 같은 공유 산출물은 현재
HEAD 기준 in-place 수정만 — 이 절차는 아래 모든 Phase에 암묵적으로
적용된다.

## 2. 단계별 진행 순서

| 단계 | 내용 | 예상 소요 |
|---|---|---|
| **Phase 0** | 환경 준비 — `git pull --rebase`, `DEEPSEEK_API_KEY` 등 시크릿 확인, 동시 세션 여부 `git log --oneline -15`로 확인 | 10분 |
| **Phase 1** | 시트 01의 27개 워크플로 + 6개 라이브 하네스 순서대로 트리거, `results/` 산출물을 표의 '상태' 열에 기록. 실패 항목만 Phase 2~4로 넘김 | 1~2시간(대부분 CI 대기) |

| **Phase 4** | 시트 09 절차로 위성 저장소 샘플링 교차검증 | 저장소당 30분 |

## 4. 최우선 미결 과제 (Phase 2~3 착수 전 반드시 먼저 볼 것)

1. **CT-04** — `expert_persona_smoketest.py`의 `compose_expert_prompt()`가
   프로덕션 `expert-session.js`의 `_composeExpertPrompt()`와 조립 순서가
   어긋나 있다(`NEXT_SESSION_HANDOFF_20260809_v2.md` §2-1 기록).
   **하네스부터 고치지 않으면 CT-05(professor 관제탑 원칙 검증, 2026-08-09
   주피터 지시 원문)의 결과를 신뢰할 수 없다.**
2. **INC-01/INC-02** — 이번 세션에서 고친 GWP orphan-tab 버그(`tool-web-search`
   → `_handleWebSearchTag`, `ksearch` → `CALL_KINTENT` 재전달)의 실사용자
   재현 확인. 배포 직후 가장 먼저 확인해야 할 항목.
3. **CT-01** — SP를 조립하는 모든 코드 경로 전수 목록화. `handleAIChat`,
   `webapp.html` BYOK 두 곳에서 이미 CONTROL-TOWER-PRINCIPLE 누락이
   발견된 전례가 있어, "이게 마지막"이라는 보장이 없다.

## 5. 워크북 사용법

- 시트 하단 탭에서 이동. `99_진행현황_대시보드`가 전체 진행률을 실시간
  집계(각 시트 '상태' 열에 `완료`라고 적으면 자동 반영).
- 모든 시트에 자동 필터 설정됨 — '우선순위' 열을 P0로 필터링하면
  긴급 항목만 추려볼 수 있다.
- '방법' 열이 `기존자동화-실행`이면 새로 설계할 필요 없이 해당 워크플로/
  스크립트를 그대로 돌리면 된다. `신규-수동`은 이 세션에서 처음 설계한
  항목이라 재현 절차를 직접 정의해야 한다. `신규-자동화 필요`는 지금은
  수동이지만 CI 가드로 승격할 가치가 있다고 판단한 항목이다.

## 6. 알려진 한계

- worker.js의 231개 REST 엔드포인트를 전수 나열하지 않고 `/biz/*`(54개,
  시트 08) 등 도메인별 대표 그룹으로 묶었다. 전수 테스트가 필요하면
  `grep -oP "pathname === '[^']+'" worker.js`로 엔드포인트 전체 목록을
  뽑아 시트 08 형식을 그대로 복제해 확장하면 된다.
- 위성 저장소 18개 중 `tools/check_wallet_sync.py`가 자체 주석으로
  "이번 조사에서 직접 검증하지 못했다"고 표시한 저장소들이 있다
  (SAT-00 참고) — 이 표도 그 미검증분을 그대로 승계했다.
