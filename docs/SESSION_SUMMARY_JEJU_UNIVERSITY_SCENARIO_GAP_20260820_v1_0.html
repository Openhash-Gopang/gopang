Architecture & Gap Analysis · 2026-08-20

제주대학교 구상 — 시나리오 추적으로 찾은 실결함과 1단계 마이그레이션

제주 지역 초중고·대학생이 혼디에서 학습을 시작하는 가상 시나리오(온보딩 → 학습일정표 → 컨텐츠 생성·공개저장 → 일일/주간/월간 지휘 → 성과 기록 → 관계자 보고)를 따라 school 저장소의 실제 구현을 추적했다. 설계 문서(시스템 프롬프트, 보고서 스키마)는 정교했지만, 실제 코드는 거의 전 구간이 미구현이거나 죽어있었다. 이 문서는 그 발견 내용과, 오늘 진행한 1단계 조치(Supabase→ PocketBase 마이그레이션)를 기록한다.

대상 저장소 Openhash-Gopang/school, Openhash-Gopang/gopang 신규 PocketBase 컬렉션 8개 (l1-hanlim) 패치 파일 school/js/config.js, school/js/report.js
Overview
개요 — 왜 시나리오 추적부터 했나

"제주대학교"를 신설 기능으로 바로 설계하기 전에, 먼저 학습자가 실제로 혼디를 쓰는 경로를 하나씩 따라가며 지금 뭐가 진짜로 동작하고 뭐가 설계 문서에만 있는 텍스트인지부터 구분했다. 결과적으로 온보딩· 스케줄링·콘텐츠 재사용·자동 보고 전 구간이 사실상 비어있거나 고장나 있었고, 그중 report.js가 완전히 멈춰있던 근본 원인(빈 Supabase 자격증명)은 제주대학교와 무관하게 지금 당장 고쳐야 하는 결함이었다. 그래서 순서를 (1) 데이터 계층 복구 → (2) 역할 분리 설계 → (3) 온보딩/ 스케줄링 신규 기능 순으로 잡았다.

Findings
시나리오 추적 결과
시나리오 단계상태근거
① 신상·적성·현재 수준 온보딩미구현_studentProfile가 null로 선언된 후 어디서도 채워지지 않음(app.js:374). 매 대화가 백지 상태로 시작.
② 학습 일정표(일/주/월) 작성미구현저장소 전체에 관련 코드 0건. curriculum_rules.json이 오히려 "사전에 세션을 작성하지 않는다"고 명시 — 설계 철학 자체가 반대 방향.
③ 일정표 기반 컨텐츠 생성 + GitHub 공개 저장미구현매 채팅이 DeepSeek 즉석 호출일 뿐, 저장/공개/재사용 파이프라인 없음. (단, klaw 저장소엔 이미 유사 패턴 존재 — 아래 참고)
④ 일일/주간/월간 학습 지휘사실상 미작동initReportScheduler() 함수 자체는 존재하나 어디서도 호출되지 않음(dead code). 호출되더라도 브라우저 탭이 계속 열려있어야 하는 setInterval 기반이라 실사용 불가 — 코드 자체 주석도 "실제 배포에서는 Cloudflare Cron Trigger 권장"이라고 인정.
⑤ 성과 측정 및 기록완전 중단report.js(612줄)는 구조는 있으나 데이터 소스(Supabase)가 죽어있어 전 함수가 조용히 실패. 근본 원인 참고.
⑥ 관계자(교사·학부모) 보고미도달스키마·양식(report_schema.json, report_table.md)은 완성도 높으나 ⑤가 죽어있어 실제 발송 0건.
⑦ 대시보드 학생 목록목업renderStudents()에 학생 6명이 이름·점수까지 하드코딩(app.js:117).
Root Cause
근본 원인 — 2026-08-12 사고 이후 방치된 빈 Supabase 자격증명

school/js/config.js:

const SUPA_URL = '' /* -2026-08-12 secret removed, see README_SECRETS_INCIDENT.md */;
const SUPA_ANON = '' /* rotate + migrate to PocketBase, see README_SECRETS_INCIDENT.md */;

8월 12일 시크릿 스캔 사고 때 키만 제거하고 "PocketBase로 마이그레이션"이라는 주석만 남긴 채 실제 전환은 안 됐다. 참조된 README_SECRETS_INCIDENT.md 파일 자체가 저장소에 존재하지 않는다 — 댕글링 참조. 다른 K-서비스 (klaw, insurance, market 등)는 이미 PocketBase 전환이 끝났는데 school만 누락됐던 것으로 보인다.

영향 범위
report.js의 5개 조회 함수(fetchStudentProfile 등) + 2개 쓰기/조회 함수 (saveReportToSupabase, fetchReports) 전부, 그리고 desktop.html· dashboard.html의 학생 대시보드 렌더링도 동일하게 빈 URL로 fetch를 시도하고 있었다(이번 세션에서는 report.js/config.js만 수정, desktop.html/dashboard.html은 남은 과제 참고).
Step 1 · Done
PocketBase 마이그레이션 — klaw 전례를 따름

klaw 저장소가 이미 같은 문제(Supabase 자격증명 소실)를 겪고 klaw_cases를 L1 hanlim PocketBase로 옮긴 전례가 있다(webapp.html의 L1_URL = 'https://l1-hanlim.hondi.net/api/collections/profiles/records' 직접 호출 패턴). 이번에도 같은 방식을 따랐다 — 별도 노드를 새로 만들지 않고, 오늘 마이그레이션한 l1-hanlim PocketBase에 school 전용 컬렉션 8개를 추가했다.

컬렉션용도비고
school_student_profiles학생 프로필(5차원 역량 포함)필드명을 report.js 기존 참조(display_name, c_score 등)에 맞춰 재사용 — 패치 범위 최소화
school_subjects학생별 활성 과목 
school_sessions세션 기록subject_id를 PocketBase relation으로 (Supabase FK 대체)
school_progress과목별 진도 
school_assessments평가 기록wrong_topics는 json, maxSize 명시
school_reports생성된 주간/월간 보고서report_data json, maxSize 50000
school_learning_schedules신규 — 학습 일정표2단계 기능이 쓸 그릇을 미리 마련(스키마만, 생성 로직은 아직 없음)
school_content_catalog신규 — GitHub 공개 컨텐츠 메타데이터본문은 PocketBase가 아니라 school 저장소 generated-content/에 커밋(klaw의 GitHub-as-store 패턴 재사용)

report.js / config.js 패치

  • config.js: SUPA_URL/SUPA_ANON/HDR 제거, PB_BASE = 'https://l1-hanlim.hondi.net/api/collections/' 추가
  • report.js: 5개 조회 함수 + saveReportToSupabase(→saveReportToPocketBase) + fetchReports 전부 PocketBase filter 쿼리로 교체
  • PocketBase 목록 응답이 {items:[...]}로 감싸져 오는 차이만 흡수하고, 이후 집계 로직(reduce 등)은 그대로 재사용 — 패치 범위를 데이터소스 교체로 한정
검증
8개 마이그레이션 파일 전부 PocketBase JSVM 스텁으로 구문·실행 점검(구문 오류 없음), relation 필드의 collectionId 상호 참조 정합성 확인, report.js/config.js node --check 통과.
Structural Conflict
역할 분리 — "학교=생활지도, 교수=지식전수" 실현 방향

school/js/config.js의 AI_PROFESSOR는 "단일, 모든 분야 담당"으로 설계돼 있고, gopang의 professor EXPERT 페르소나(307개 리프, K-12 과목 매핑까지 완성)와 연동하는 코드는 school 저장소 어디에도 없다(expert-registry, CALL_EXPERT 검색 0건). 지금은 K-School이 지식 전수까지 전부 자체적으로 다 하는 구조라, "학교 교사=생활지도, professor 페르소나=지식전수" 분리를 실현하려면 다음 재설계가 필요하다.

제안 방향(설계만, 아직 미구현)

  • K-School의 시스템 프롬프트에서 과목 지식 전달 파트를 축소하고, 대신 학생 상태 파악·정서 지원·학습 동기부여·일정 조율("오늘 뭐 할까?", "잘 하고 있어" 같은 오케스트레이션 역할)에 집중하도록 재작성
  • 과목 질문이 들어오면 K-School이 직접 답하지 않고 gopang AC 라우팅을 통해 professor EXPERT 페르소나로 위임 — klaw가 KLAW_RELAY_URL로 hondi-proxy를 거치듯, school도 유사한 relay/handoff 엔드포인트가 필요
  • "제주대학교"는 이 위임 구조의 상위 조직 단위로, 초중고(생활지도 중심 K-School 인스턴스) + 대학(전공 심화, professor 페르소나 비중 더 큼)을 함께 관장하는 SP-ORG 성격의 엔티티로 설계 — L2(제주시/서귀포시)와 유사한 레벨이지만 교육 도메인 전용
범위 안내
이 섹션은 설계 방향 제시이며, 실제 AC 라우팅 변경이나 system_prompt.txt 재작성은 이번 세션에서 진행하지 않았다. 데이터 계층이 막 복구된 상태라, 이 재설계는 report.js 정상 동작 확인 이후 별도 세션에서 진행하는 걸 권한다.
Step 2 · Spec Only
온보딩 + 학습 일정표 생성 — 다음 구현 스펙

오늘 마련한 school_learning_schedules/school_content_catalog 스키마를 채우는 기능 스펙이다. 코드는 아직 없다.

  1. 온보딩 대화 플로우: 첫 접속 시 school_student_profiles.onboarding_completed가 false면, K-School이 몇 개의 질문(현재 학년, 자신 있는/어려운 과목, 장래 희망, 하루 가용 학습시간)으로 프로필을 채우고 PB_BASE로 upsert. 완료되면 true로 갱신.
  2. 일정표 생성: 온보딩 직후 + 매 period 종료 시, 프로필+과거 진도(school_progress)를 바탕으로 school_learning_schedules에 daily/weekly/monthly 레코드 생성. plan_items마다 content_ref가 비어있으면 3번으로.
  3. 컨텐츠 생성 + GitHub 공개 저장: school_content_catalog에서 같은 (subject_id, stage, topic) 조합이 이미 있으면 재사용(reuse_count +1), 없으면 DeepSeek으로 생성 → generated-content/<stage>/<subject>/<slug>.md로 school 저장소에 커밋(klaw의 GitHub API 직접 커밋 패턴 재사용) → catalog 레코드 생성.
  4. 일일/주간/월간 지휘: 브라우저 setInterval(현재 dead code) 대신 Cloudflare Worker Cron Trigger로 교체 — report_schema.json이 이미 명시한 "매주 일요일 23:59" 같은 트리거를 실제로 동작시키는 유일한 방법.
