# GOV-TASK-GAP-TRACKER 사용법

이 폴더의 `GOV-TASK-GAP-TRACKER_2026-08-20.csv`는 [[gov-task-904-gap-filling]]
프로젝트(REQUIRED_DOCUMENTS_REGISTRY 904개 기관 공백 채우기)의 **진행상황
추적 표**다. `gov-tree-hondi-readiness-audit.xlsx`(전수조사 시트, Q1=Y & Q2=N
필터링된 904행)를 원본으로 만들었고, 이후 상태 갱신은 원본 xlsx가 아니라
**이 CSV에서만** 한다 — xlsx는 최초 스냅샷일 뿐, 계속 갱신되는 건 이 파일이다.

| 경로 | 저장소 내 SP 파일 경로(`prompts/gov-tree/` 기준 상대경로) |

| **상태** | `미착수` / `완료` / `제외(오탐)` / `재정의` / `진행중` 중 하나 |
| 비고 | 상태 판단 근거, 등록한 task_key, 오탐 사유 등 |
| PR | 완료 시 병합된 PR 번호 |
| 완료일 | 완료 처리된 날짜 |

## 상태값 정의

- **미착수**: 아직 아무 작업 안 함(기본값)
- **완료**: §3의 5단계 체크리스트(SP 본문 수정, REQUIRED_DOCUMENTS_REGISTRY
  등록, AGENCY_TO_DEPT_TARGET/GOV_TASK_AGENCY_TO_ORGID, 필요시
  division-tables.js)를 실제로 마치고 PR이 main에 병합된 상태
- **제외(오탐)**: 실사 결과 애초에 GOV_TASK 배선이 필요 없다고 판단된 것
  (예: SP-EXP-EMERGENCY — 응급신고 안내이지 인허가가 아님). **주의**:
  "안내형으로 보여서 제외"는 2026-08-20에 07-org 전체(312건)에 한 번
  잘못 적용했다가 정정된 전례가 있다 — 공공기관은 안내로만 끝나지 않고
  반드시 실제 업무·집행이 있다는 원칙(사용자 지시)을 어기지 않는 한도
  내에서만, 개별 파일 단위로 확실한 근거가 있을 때만 이 상태를 쓸 것.
  카테고리 전체를 이 상태로 일괄 처리하지 말 것.
- **재정의**: 진짜 공백은 맞지만 REQUIRED_DOCUMENTS_REGISTRY 패턴이 안
  맞아 다른 종류의 작업으로 다시 정의된 것(예: 01-do 최상위 도청 SP —
  실제 서류를 심사하는 게 아니라 하위 실·국에 위임하는 조정 레이어라서,
  "위임 안 되는 광역 인허가의 처리 경로 명시"가 필요. 아직 그 재정의된
  작업 자체는 미착수).
- **진행중**: 작업 시작했지만 PR 미병합 상태(세션 중간에 끊길 때 이
  상태로 남겨두고 비고에 어디까지 했는지 적을 것).

## 상태 갱신 시 주의 — 경로 오매칭

CSV를 스크립트로 갱신할 때 `경로.str.contains('WELFARE-DISABLED')`처럼
부분 문자열로 매칭하면, 04-city의 `SP-CITYDIV-*-WELFARE-DISABLED`뿐
아니라 이름이 비슷한 02-do-dept의 `SP-DIV-WELFARE-DISABLED`까지 같이
걸려서 손 안 댄 행이 실수로 "완료"가 되는 사고가 실제로 있었다
(2026-08-20). **경로는 반드시 정확히 일치(`==`)시키거나, 최소한
분류(01-do/02-do-dept/... 열)까지 같이 조건에 넣을 것.**

## 복지 계열(WELFARE) 작업 시 반드시 먼저 확인할 것

**2026-08-20 시점 복지위생국 6개과 전부 완료**(위생관리·장애인복지·노인복지·
기초생활보장·여성가족·주민복지, 제주시/서귀포시) — 이 섹션은 앞으로
02-do-dept나 다른 시(市)에 같은 성격의 복지 계열이 나타날 때를 위해 남긴다.

개인 복지급여 신청(장애인등록·기초연금·기초생활보장·한부모가족지원 등)은
전통적으로 **읍·면·동(주민센터)이 1차 접수, 시청 복지 담당국이 최종 심사**
하는 2단계 구조다(`SP-EMD-TEMPLATE_v1.3.md` §3 "주민복지팀" 참조). 05-emd는
이 감사 스캔 대상이 아니라서(정적 파일 없이 동적 렌더링), 시청 SP의
§INPUT_SCHEMA를 그대로 믿고 "시청이 접수까지 다 한다"고 등록하면 사실과
다르다. 대신 복지로(bokjiro.go.kr) 온라인 접수 선례를 따라 "시청 명의
온라인 접수 통로 — 심사는 원래도 시청" 프레이밍으로 SP §1-2에 disclaimer를
넣는 패턴을 확립했다(`SP-CITYDIV-*-WELFARE-*_v1.1.md` 전체 참조).

**예외**: 긴급복지지원(긴급복지지원법 제7조)은 법 자체가 "관할 시장·군수·
구청장에게 구술 또는 서면으로 직접 요청" 가능하다고 명시해 읍면동 경유가
필수가 아니다 — 이런 예외가 있으니 **매번 개별 법령을 웹검색으로 재확인
할 것, "복지=무조건 읍면동 경유"로 일반화하지 말 것.**

## 원본 감사의 구버전 중복 행 주의

`gov-tree-hondi-readiness-audit.xlsx`는 저장소를 한 시점에 스냅샷 스캔한
것이라, 같은 기관·부서의 v1.0/v1.1/v1.2가 각각 별도 행으로 잡혀 있는
경우가 많다(01-do JEJU-DO-SP가 v1.0/v1.4/v1.5 세 행으로 잡힌 것과 동일
패턴, 2026-08-20 서귀포 안전도시건설국 6개과에서도 재확인). **미착수로
보이는 행을 작업하기 전에 항상 `find prompts/gov-tree -iname "*{기관명}*"`
로 실제 디스크의 최신 버전을 먼저 확인할 것** — 이미 상위 버전으로
완료됐는데 구버전 행만 미착수로 남아있는 경우가 있다.

## 관할 권한 소재(위임 여부) 확인 — 청정환경국류 작업 시 필수

청정환경국 환경관리과/기후환경과(2026-08-20)에서 발견: 대기환경보전법
등 환경 관련 인허가는 법조문상 "시·도지사"(제주도지사) 권한인데, 시청
SP는 "관내 인허가를 집행한다"고 서술하고 있다 — 제주특별법상 행정시
사무위임을 전제한 것으로 보이나 **이번 조사에서 위임 근거조항을 확정
하지 못해 TBD로 남겼다**(PR#482). 환경/보건/농수산 등 원래 광역단위
권한인 분야를 작업할 때는 항상 이 위임 여부를 의심하고, SP에 정직하게
TBD로 표시할 것 — 확인됐다는 근거 없이 임의로 "위임됐다"고 단정하지
말 것.

## 지원사업류(재량적 선정) 작업 시 주의 — 법률 아닌 행정지침/조례 근거일 수 있음

마을기업 지정신청(2026-08-20)에서 확인: 04-city/07-org의 "지원사업 신청"류
(소상공인 지원금·일자리사업 참여·정보화교육 등)는 건축허가·등록처럼
개별법 조항이 있는 게 아니라 **행정지침이나 지방자치단체 조례**가 유일한
근거인 경우가 많다(마을기업은 한국법제연구원이 "명확한 법적 근거 없음"
이라고 확인한 사례). 이런 항목을 등록할 때는:
1. 국가법령정보센터·법제처에서 관련 법률을 먼저 찾아본다.
2. 없으면 소관 중앙부처의 "○○사업 시행지침"을 찾아 legal_basis에 지침명·
   발행기관을 그대로 적는다(허구의 조항번호를 지어내지 말 것).
3. SP §1-2에 "법률이 아닌 행정지침 근거"임을 반드시 명시한다.
4. 가능하면 제주시·서귀포시 개별 조례 원문 확인도 시도하되, 못 찾으면
   지침 근거로 진행하고 TBD로 남긴다.

## 01-do 도지사 전속 사무 — 정적 파일이 아니라 템플릿에 반영됨

01-do의 `JEJU-DO-SP_v1.x.md`는 **2026-07-21부로 죽은 파일**이다 — 실제
도청 SP는 `prompts/gov-tree/01-do/templates/SP-PROVINCE-TEMPLATE_v1.2.md`
+ `province-master-data.json`을 `gov-router.js`의 `_renderProvinceTemplate()`
로 런타임 조합해서 만든다. 도지사 전속 GOV_TASK(예: 개발사업 시행승인)는
이 템플릿의 `{고유사무_문구}` 자리표시자(2026-08-20 신설)에 넣는다 —
`province-master-data.json`의 해당 도 레코드에 문구를 채우면 된다.
**정적 파일(`01-do/JEJU-DO-SP_v1.x.md`, `JEJU-DO-AGENT-COMMON_v1.2.md`)을
고치는 건 아무 효과가 없다** — 다음 세션이 다른 도(경기·서울 등)의
도지사 전속 사무를 찾으면, 이 방식(province-master-data.json의
`고유사무_문구` 필드)을 그대로 쓸 것. 나머지 14개 도는 아직 빈 문자열
(TBD)이다. `JEJU-DO-AGENT-COMMON_v1.2.md`도 같은 방식으로 대체됐을
가능성이 있으나 이번 세션에서 확인 못함 — 다음 세션이 먼저 확인할 것.
