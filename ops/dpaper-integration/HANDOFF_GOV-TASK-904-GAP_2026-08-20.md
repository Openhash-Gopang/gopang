## 3. 새 항목을 GOV_TASK에 배선하는 정확한 절차 (검증된 5단계 + 신규 원칙)

1. **SP 파일 열어서 §INPUT_SCHEMA 확인** — "○○ 신청/신고/등록/허가"가
   실제 트랜잭션형인지, 아니면 예약/문의/정책안내형인지 먼저 판별.
   `grep "^- \*\*입력\*\*" <파일>`로 빠르게 훑을 수 있다.
2. **웹검색으로 실제 법령 확인** — "○○법 제○조" 형태로 정확히. 시행령·
   시행규칙까지. **절대 "건축법"처럼 뭉뚱그리지 말 것.** 법률이 아니라
   행정지침·조례뿐인 경우(예: 마을기업)도 있다 — 그 경우 legal_basis에
   "법률 아닌 행정지침/조례" 임을 정직하게 명시하고 지침명을 그대로 적을 것.
3. **관할 권한 소재 확인** — 특히 도(道) 단위 항목은 "도지사 고유 권한"인지
   "행정시(시청)에 위임된 사무"인지 반드시 확인. 애매하면 웹검색으로
   조례·특별법을 찾아서 확정할 것(예: 제주는 제주특별법 제17조제5항이
   일반 위임 원칙, 개별 조례가 예외를 규정하는 패턴).
   **개인 복지급여류는 읍면동 1차접수·시청 최종심사 2단계 구조**가
   흔하다 — 이 경우 05-emd(읍면동, 정적 파일 없이 동적 렌더링이라 이
   감사 스캔 대상 아님)를 새로 만들 필요 없이, 복지로(bokjiro.go.kr)
   선례를 따라 "온라인 접수 통로" 프레이밍으로 시청 명의 등록하면 된다.
4. **REQUIRED_DOCUMENTS_REGISTRY 등록**(worker.js) — `agency:task_key`
   형식. agency 코드는 시청(jejusi/seogwipo)·도청(jeju)·기관 고유코드
   (jcgf, jejufire 등) 중 그 기관 성격에 맞는 것.
5. **AGENCY_TO_DEPT_TARGET 등록**(worker.js) — 반드시 `agency:task_key`
   세분 키로. `do-dept:{도메인}`(도청 실·국) 또는 `city-dept:{시}:{도메인}`
   (시청 국) 또는 `org:{기관코드}`(07-org 출자출연기관) 셋 중 하나.
   유효한 도메인 목록은 `src/worker/dept-task-handler.js` 상단 참조.
6. **SP 본문에 §1-2 섹션 추가**(GOV_TASK 접수·심사·보완·의견제출) —
   기존에 등록된 사례들(`SP-CITYDIV-*-WELFARE-*_v1.1.md` 등)을 템플릿
   삼아 그대로 패턴 복사. 정직하게 밝힘(관할·행정지침 여부 등) 문단을
   빠뜨리지 말 것.
7. **버전 헤더 갱신 + rename(v1.0→v1.1 등) + division-tables.js(또는
   gov-router.js) file: 포인터 동기화.**
8. **`python tools/check_stale_refs.py`로 검증** — "576건(또는 그 이상)
   정상, 문제 0건" 나와야 함.
9. **추적표 CSV 갱신**(경로는 정확히 `==` 일치로, 부분 매칭 쓰지 말 것 —
   §4-⑤ 참조).

## 4. 반복된 실수 — 이번 세션에 실제로 겪은 것

**① "이미 있는 걸 모르고 새로 만들기" — 이번엔 정반대로 "이미 없어진
걸 모르고 죽은 파일 고치기"로 변형돼서 재발했다.** 01-do의
`JEJU-DO-SP_v1.5.md`에 §1-3을 새로 써넣었는데, 그 파일이 2026-07-21부로
이미 `SP-PROVINCE-TEMPLATE`+`province-master-data.json`으로 완전히
대체된 죽은 파일이었다. **교훈**: 정적 파일을 고치기 전에 항상
`grep -n "<파일명>" src/gopang/gov/gov-router.js`로 그 파일이 실제로
fetch되는지 확인할 것 — "정적 파일 fetch"에서 "템플릿+데이터 렌더링"
으로 조용히 전환된 계층이 있을 수 있다(01-do가 그랬다, 다른 계층도
그럴 수 있다).

**② sandbox를 `git reset --hard origin/main`으로 초기화하기 전 항상
미병합 작업이 있는지 확인할 것 — 이번 세션에서 두 번이나 병합 전
작업(4·3보상금/도유재산/개발사업 워커 등록)을 날려서 재작업했다.**
`git status --short`로 미커밋 변경사항이 있는지, 사용자에게 아직
"병합됐다"는 확인을 못 받은 zip을 전달한 상태인지 항상 먼저 체크할 것.

**③ 감사(audit) 원본의 키워드 매칭이 오탐을 낸다 — 카테고리 전체를
일괄 판단하지 말 것.** 07-org 전체(312건)를 "안내형이라 의도된 설계"
로 한 번 잘못 결론 냈다가, 사용자가 "공공기관은 안내로만 끝나지
않는다"고 정정해서 방향을 되돌렸다(JCGF 사례로 실증). **교훈**: 카테고리
수준의 일반화("이 그룹은 전부 X 성격")는 표본 몇 개로 성급하게 내리지
말고, 개별 사례를 실증해가며 판단할 것 — 특히 사용자가 이미 원칙을
말한 뒤에는(예: "안내만 하는 공공기관은 없다") 그 원칙을 존중해서
작업할 것.

**④ 도(道) 최상위 계층("도지사")도 위임 경로 안내만 하는 순수 조정
레이어가 아니라, 법령에 명시된 고유 사무를 수행하는 단위일 수 있다.**
01-do를 "재정의"(등록 대상 아님)로 넘겼다가, 사용자 지적으로 실제
도지사 전속 사무(개발사업 시행승인)를 찾아 등록했다. **교훈**: 최상위
계층이라고 해서 자동으로 "정책총괄·집행은 하위기관"이라고 단정하지
말 것 — 그 계층이 직접 처리하는 법정 사무가 있는지 반드시 확인.

**⑤ CSV 갱신 시 경로를 부분 문자열로 매칭하면 안 건드린 행이
잘못 완료 처리된다.** `str.contains('WELFARE-DISABLED')`가
04-city뿐 아니라 이름이 비슷한 02-do-dept 항목까지 걸려서 실수로
"완료" 처리한 적 있다. **반드시 정확히 일치(`==`)시키거나 분류 열까지
같이 조건에 넣을 것.**

**⑥ 관할 권한(위임 여부)을 확인 안 하고 등록하면 틀린 접수 창구를
만들 위험이 있다 — 두 번 실제로 걸렸다.** 청정환경국(대기배출시설,
법조문상 도지사 권한인데 시청이 서술)은 위임 여부를 TBD로 명시하고
넘어갔고, 장애인복지과(개인 복지급여)는 읍면동 1차접수 구조를
찾아내 복지로형 disclaimer로 해결했다. **패턴**: 등록 전에 항상
"이 업무 법조문상 권한자가 실제로 이 SP(시청/도청)가 맞는가"를
웹검색으로 확인할 것 — SP 본문이 "우리가 처리한다"고 써있다고 믿지
말 것(SP 본문 자체가 실사 안 된 채로 작성됐을 수 있다).

- **09-national(437건)**: 표본조사(75건 중 20건)만 했다 — 대체로 진짜
  공백으로 보이나, **혼디가 국가기관 서류를 실제로 접수·심사까지
  대행하는 게 애초에 제도적으로 가능한 범위인지**부터 확인이 필요.
  일부 표본은 "SP-부서-입출력-마스터목록" 같은 카탈로그/색인 파일이라
  실제 작업 대상이 아닐 수 있음(추가 확인 필요).
- **benefit-categories(13건)**: 표본 전부가 "신청은 읍면동 또는

  아예 안 맞을 가능성이 큼. 어떤 종류의 작업이 맞는지부터 재정의 필요.

## 6. 작업 순서 제안 (강제 아님)

1. **JEJU-DO-AGENT-COMMON_v1.2.md 죽은 파일 여부 먼저 확인** — 5분
   이내 끝날 일이고, 잘못 알고 또 죽은 파일에 쓰는 실수를 막는다.
2. **02-do-dept 나머지 40건** — 규모가 다루기 좋고(42건), 이미 패턴이
   검증된 카테고리. SP-DO-*(실국) 22건은 템플릿 전환 여부부터 확인,
   SP-DIV-*(과) 20건은 그대로 정적 파일 편집.
3. **03-do-agency 나머지 19건** — HERITAGE 조례 재조사부터.
4. **07-org 표본조사 확대**(예: 20~30개 더) — 규모(312건)가 커서
   작업량 재추정이 먼저 필요. 사용자 원칙("안내형이라고 억지로 넘기지
   말 것")을 지키면서.
5. **09-national** — 대행 범위(제도적 가능성) 먼저 확인한 뒤 착수.
6. **benefit-categories** — REQUIRED_DOCUMENTS_REGISTRY가 안 맞으면
   어떤 작업이 맞는지 사용자와 논의.
