# SP-EVAL-TRACKER 사용법

이 폴더의 `SP-EVAL-TRACKER.csv`는 **SP 전수 평가·보완 프로젝트**의 진행상황
추적 표다. `prompts/sp-catalog-categories.json`(2,011개 SP 전수 목록)을
원본으로 만들었고, 이후 상태 갱신은 원본 JSON이 아니라 **이 CSV에서만** 한다
— JSON은 카탈로그(분류 체계)이고, 이 CSV가 작업 진행상황 그 자체다.

이 프로젝트는 [[gov-task-904-gap]](`ops/dpaper-integration/`)와는 **다른
프로젝트**다 — 그쪽은 904개 기관의 법적 근거·필요서류 공백을 채우는 작업이고,
이쪽은 전체 SP를 [SP 평가 방법론](https://hondi.net/pages/sp-evaluation-methodology.html)
7개 기준으로 채점하고 미비점을 고치는 작업이다. 다만 세션이 여러 개로
쪼개져도 다음 세션이 이 CSV만 읽으면 이어받을 수 있도록, 같은 트래커
패턴을 그대로 가져다 썼다.

## 목적

1. 2,011개 SP 전체를 평가해 완성도(%)를 매긴다.
2. 평가 과정에서 발견한 미비점 중 SP 파일 자체를 고쳐서 해결할 수 있는
   것은 그 자리에서 수정한다.
3. 최종 결과(완성도·세부 배점)는 `prompts/sp-status.json`에 반영해
   `pages/prompt-status.html`에서 누구나 볼 수 있게 한다.
4. (별도 트랙) 각 SP를 실제 자연어 발화로 살아있는 상태에서 테스트할 수
   있는 "테스트 버튼" 기능을 만든다 — 이건 콘텐츠 작업이 아니라 플랫폼
   기능이라 이 트래커의 진행 단위와는 별도로 진행한다.

## 열 설명

| 열 | 의미 |
|---|---|
| 우선순위그룹 | 아래 "우선순위 순서" 참조 |
| 분류 | 카테고리 라벨 (하위분류가 있으면 `상위 · 하위` 형태) |
| 파일 | `prompts/` 기준 상대 경로 |
| 이름 | 카탈로그에 등록된 SP 이름 |
| 상태 | 미착수 / 평가완료 / 수정완료 / 재평가완료 / 제외 |
| 완성도(%) | 재평가완료 상태가 된 시점의 최종 점수 (7개 기준 균등가중 평균) |
| 미비점요약 | 평가 중 발견한 문제를 한 줄로 (구조적 결함이라 이번 배치에서 못 고친 경우 여기에 남겨서 다음 배치가 이어받게 한다) |
| PR | 이 SP를 수정한 PR 번호 |
| 완료일 | 재평가완료로 표시한 날짜 |

**상태값 전이**: 미착수 → 평가완료(7개 기준 채점만 끝남, 아직 수정 전)
→ 수정완료(미비점 수정 반영) → 재평가완료(수정 후 다시 채점해 완성도 확정,
`sp-status.json` 반영됨). 문제가 없어서 수정이 필요 없었던 SP는 평가완료
단계에서 바로 재평가완료로 넘어갈 수 있다(수정 단계 생략).

"제외"는 실제로는 SP가 아니거나(설계 문서, 스키마 파일 등) 이 평가 방법론이
적용되지 않는 경우에 쓴다 — 사유를 미비점요약 칸에 남긴다.

## 우선순위 순서 (2026-08-30, 주피터 승인)

상속 트리 상단을 먼저 고치면 하위 다수가 자동으로 혜택을 보기 때문에,
아래 순서로 진행한다. 반드시 이 순서를 지킬 필요는 없지만(세션마다 관심
영역이 다를 수 있음), 특별한 사정이 없으면 이 순서를 기본값으로 한다.

1. **1-최상위공통 (5건)** — `UNIVERSAL-common`, `UNIVERSAL-INTEGRITY`,
   `PROFESSIONAL-common`, `K-Public_common`, `SP-10_kpublic(kgov)`.
   전체 SP가 직간접으로 상속하는 최상위 원본이라 영향력이 가장 크다.
2. **2-핵심SP (13건)** — `core-prompts.html`에 정리된, worker.js가
   예외 없이 강제 주입하거나 조건부로 실행하는 SP들. 트래픽이 가장 크다.
3. **3-고위험전문직 (110건)** — 의사·치과의사·간호사·약사 등 의료 계열과
   변호사·세무사·회계사·법무사 등 법률·재무 계열. 오류의 대가가 큰
   영역부터 처리한다.
4. **4-정부기관라우팅 (1,269건)** — gov-national(500) → gov-org(374) →
   gov-city(122) → 나머지 gov-tree 카테고리 순.
5. **5-나머지 (614건)** — 교수(356) 등 나머지 전문직 페르소나, 경제·산업,
   민원·서비스, K-서비스, 시스템 잔여분.

## SP당 처리 절차

1. SP 원문을 정독하고 스스로 선언한 목적·소관을 확인한다.
2. [SP 평가 방법론](https://hondi.net/pages/sp-evaluation-methodology.html)의
   7개 기준으로 채점하고, 각 기준에 근거 한 줄을 남긴다 → 상태를
   **평가완료**로 바꾼다.
3. [SP 작성 방법론](https://hondi.net/pages/sp-writing-methodology.html)
   체크리스트로 구조적 결함(상속 위반, 필수 섹션 누락, 형제/부모 관계
   오선언 등)이 있는지 확인한다.
4. 그 자리에서 고칠 수 있는 미비점(정직성 표기 누락, 예외처리 부재,
   데이터 공백 미선언, 개정이력 누락 등)은 SP 파일을 직접 수정한다 →
   상태를 **수정완료**로 바꾼다. 사실관계 자체가 의심스러우면(기관 정보,
   연락처 등) 웹서치로 재검증한다.
5. 여러 SP에 걸친 구조적 문제(잘못된 상속 관계 등)는 개별 수정 대신
   미비점요약에 남겨두고 별도 배치로 일괄 처리한다 — 파급 범위가 넓은
   변경을 SP 하나 고치다가 섣불리 반영하지 않는다.
6. 수정 후 다시 채점해 완성도(%)를 확정한다 → 상태를 **재평가완료**로
   바꾸고 `prompts/sp-status.json`에 반영한다.
7. 이 CSV의 해당 행을 갱신한다(완성도·미비점요약·완료일).
8. 배치 단위(카테고리 1~2개, SP 20~40건 선)로 모아 패치를 만들고
   pull → rebase → PR → merge로 반영한다.

## 알려진 미확정 사항 (다음 세션에서 결정)

- 4번 단계에서 사실관계 재검증(웹서치)을 매번 할지, 명백히 틀린 경우만
  할지는 아직 확정하지 않았다 — 세션당 처리량에 영향을 준다.
- "테스트 버튼" 기능(축 B)은 아직 설계 전이다. 실제 서비스가 SP를 로드해
  LLM을 호출하는 코드 경로, 사용 중인 LLM/키, 비용·레이트리밋 정책을
  확인하는 정찰이 선행되어야 한다.

### 6차 배치에서 확인한 것

**M1(응급 최우선 트리아지) 임계값의 세부분야별 조정**이 의사 페르소나
군에서 특히 정교하다 — 신경과(뇌졸중 골든타임), 산부인과(자간전증·
태반조기박리 등 산과 특유 응급신호), 흉부외과(급성 대동맥박리)는 부모
SP보다 더 엄격한 M1을 적용하도록 명시적으로 재정의되어 있다. 반대로
응급성이 낮은 세부분야(병리과·영상의학과·예방의학과 등)는 M1을
건드리지 않고 그대로 상속한다 — 위험도에 비례한 안전장치 배분이
합리적으로 이루어지고 있음을 확인했다.

**소아청소년과의 특별한 경고**: "용량·정상범위가 성인과 완전히 다르다"는
것을 가장 중요한 차이로 명시해, 성인 기준을 그대로 적용하면 위험할 수
있음을 스스로 경고한다.

**"변호사 페르소나 기준 품질평가"가 이 시점(2026-08-08)에 감정평가사·
손해사정사·재무설계사·한의사에도 동일하게 적용**돼 확신도 라벨·강제전환
트리거가 신설됐다 — 5차 배치에서 확인한 패턴과 정확히 같은 시점, 같은
방식의 시스템 전체 개선이었다.
